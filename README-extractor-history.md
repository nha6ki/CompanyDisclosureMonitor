## 今回動く処理

1. `filings.json` に記録したNVIDIAの5件の原文を読みます。
2. SHA-256で前回使用した本文と同じファイルであることを確認します。
3. 非表示のデータなどを除き、Item見出しごとに本文を分けます。
4. 辞任受理、退任意向、買収契約、決算発表、提携、暫定役職、支払義務の上限などの英語表現に合う箇所を探します。
5. 優先順位に従い、異なる段落から各提出につき最大2箇所、1箇所12語以内を表示します。

抽出処理は前回の日本語要約を読みません。会社名・人名・日付・金額・提出番号に応じて
答えを返す処理でもありません。`reference_review.html` は、抽出後の比較画面を作る際だけ読みます。
日本語の自動要約、財務数値の検証、予定の実現確認は実装対象に含めていません。

## 実行

Python 3.10以上。追加パッケージやLLMのAPIキーは不要です。

既存のCompany Disclosure Monitorに保存した原文を使う場合：

```bash
python extract_evidence.py --source-dir /path/to/cache/NVDA
```

指定ディレクトリの下に、`0001045810-26-000082/primary.html` などの5件が必要です。
今回の実行には既存プロジェクトの保存済み本文を使いました。新たなSEC通信は行っていません。

保存済み原文がない場合、SECから対象5件の本文を取得して実行できます。
連絡先メールアドレスを自分のものに置き換えてください。

```bash
python extract_evidence.py --fetch --contact your-address@example.com
```

または環境変数 `SEC_CONTACT_EMAIL` を設定して `--fetch` を指定します。
連絡先はSECへのUser-Agentに使用し、出力や設定には保存しません。メールは送信しません。
原文は `cache/<提出番号>/primary.html` に保存します。既存ファイルは自動で上書きしません。
通信は逐次、最低1.1秒間隔です。HTTPエラー（403・429を含む）や通信失敗時は後続の取得を止め、
自動再試行しません。取得失敗や原文変更は、候補が見つからない場合と区別して出力します。

再実行：

```bash
python extract_evidence.py
```

元のHTML本文はこのZIPに含めていません。URLとハッシュを `filings.json` に保持しています。
SECから取得した原文が固定サンプルと異なる場合は比較を止めます。ハッシュを無条件に更新せず、
原文・参照要約を確認してからサンプルを更新する必要があります。

## 出力と終了コード

| ファイル | 内容 |
|---|---|
| `output/nvidia_five_filings_review.html` | 前回の日本語要約と今回の自動抽出候補を比較する画面 |
| `output/evidence.json` | 使用ルール、提出番号、Item、原文ハッシュ、根拠の位置 |
| `filings.json` | 固定した5件のURL・日付・登録項目・本文ハッシュ |
| `reference_review.html` | 前回の参照用レポート。自動抽出の入力には使わない |

JSONは引用文を重複保存せず、本文を正規化したテキストのブロック番号（1始まり）と、
そのブロック内の文字位置（0始まり・終端を含まない）を保存します。
`visible_blocks(raw)[block_number - 1][char_start:char_end]` で表示した抜粋を再構成できます。
段落のSHA-256も記録します。段落番号はHTMLソースの行番号ではありません。

終了コードは、全5件で候補を得た場合が `0`、候補なし・資料未取得・原文変更・取得失敗を
含む場合が `2`、設定や入出力のエラーで完了できなかった場合が `1` です。
`0` は要約が正しい、または開示に誤りがないという判定ではありません。

## 検証と限界

```bash
python -m unittest -v test_extract_evidence.py
```

2026年11月17日の固定5件では、各2候補、計10候補を抽出しました。
15件のテストで、別の会社名・人名・日付、引用位置の復元、非表示領域、分割された見出し、
否定・仮定表現、将来見通し欄、項目の切替、該当表現なし、資料欠落、本文変更、403・429停止を確認しました。

最初の5件を見ながらルールを設計しました。その後、別のNVIDIAの5件による限定的な確認を行い、
未対応の出来事や任命表現の違いによる取りこぼしを確認しています。体系的な精度評価はまだ行っていません。
対応する英語表現が少なく、言い換えを拾えない場合があります。否定・仮定・伝聞の除外も
完全ではありません。候補なしは「出来事がない」という意味ではありません。
短い抜粋には主語・条件などが収まらない場合があります。前後の文脈は原文で確認してください。
HTMLの段落・見出し構造が異なる資料では、抽出漏れが起きる可能性があります。

項目番号の不一致は確認候補として残します。発行者の誤りだと自動判定せず、
担当者の確認記録を自動で「確認済み」に変更することもありません。
